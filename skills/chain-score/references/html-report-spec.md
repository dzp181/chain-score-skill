# HTML 报告输出规范

本技能的全部结论以**单文件 HTML** 交付。默认路径 `outputs/chain-score-<主题拼音或英文>-<YYYYMMDD>.html`。

## 1. 交付硬约束

1. **单文件、自包含**：所有 CSS/JS 内联，不引用外部 CDN、字体、图片、接口。`file://` 双击即可用。
2. **数据即内容**：所有研究内容写进 `window.REPORT` 对象，由模板渲染。禁止把结论散写进标签。
3. **真实数据必须带日期**：每条证据写 `d`（发布日期）与 `src`（来源名），能定位原文的补 `url`（链接）与 `page`（页码/问答编号）。取不到写 `[MISSING]`，不留空、不编造。
4. **财务数字不得估算**：`FIN` 里每个数都要来自定期报告或交易所行情；口径不明就不填，写 `"—"` 并在脚注说明，不用"约""大概"糊过去。
5. **示例数据必须挂标**：`meta.demo = true` 时页面显示"示例数据"徽标与脚注，不得移除。
6. **末尾声明**：页脚固定"本报告仅供研究参考，不构成个人投资建议"。

## 2. 版面结构（必须按此顺序）

```
┌ 主题概览 ────────────────────────────────────────────────────────────┐
│ 产业链 / 热点名 + 一句话结论 + 3 个统计   [示例徽标] [复制结论] [研究日] │
├ 产业链层级排序（3–5 层，卡点强度 0–10，先定层级再选公司）──────────┤
├ 优先研究标的财务口径（11 列表格，可横向滚动）───────────────────────┤
├ 左：优先研究标的（按综合分从高到低）┬ 右：选中标的详情 ──────────┤
│ 01 中际旭创 84  ▓▓▓▓▓▓▓▓░░           │ 名称 / 代码 / 分数环 / 定级    │
│ 02 天孚通信 80  ▓▓▓▓▓▓▓░░░           │ 五维评分（5 项横排，可点开）   │
│ 03 新易盛   76  ▓▓▓▓▓▓░░░░           │ 核心洞察                       │
│ 04 源杰科技 71  ▓▓▓▓▓▓░░░░           │ 产业链位置 ｜ 排序理由         │
│ 05 光迅科技 61  ▓▓▓▓▓░░░░░           │ 证据链（带日期 + 来源链接）    │
│                                      │ 主要风险 + 失效条件            │
│                                      │ 关键观察位（4 格）             │
│                                      │ 数据缺口 / 下一验证            │
└──────────────────────────────────────┴────────────────────────────────┘
```

**为什么是这个顺序**：先给层级结论（哪一层卡），再用财务口径验证这几家公司**是否真在这条链上赚钱**，最后才给公司结论（该层里研究谁）与单家详情。层级没排清楚就给股票，等于跳过研究直接给答案；财务没对上，等于讲了一个和报表无关的故事。

**没有搜索框**。报告是技能一次运行产出的静态快照，输入主题在技能调用时就已确定，页面内再放搜索框无处可查，纯属装饰，因此不设顶栏搜索。切换主题用主题头部的 chips。

**响应式**
- ≥1180px：左 350px + 右自适应，左栏 sticky
- 900–1180px：左 306px，层级卡 2 列，财务表横向滚动
- <900px：单列，层级卡纵向排列，标的列表 1–2 列；点选标的后自动滚到详情
- <760px：卡片标题与右侧说明改为上下两行，避免挤压
- <760px：财务表保留全部 11 列，靠 `.finwrap` 横向滚动，**不隐藏列、不改成卡片堆**（数字一列一列对着看才有意义）

## 3. 数据模型

写入模板顶部 `const REPORT = {...}`，字段不可缺（缺则填 `null` 或 `[MISSING]`）：

```js
{
  meta: {
    generatedAt: "2026-10-17 23:10",
    demo: false,
    rubricVersion: "1.0",
    market: "A股",
    finPeriod: "2026Q3",        // 财务口径所属报告期，必填
    priceDate: "2026-10-16",    // 股价与市值取数日，必填
    finNote: ""                 // 可选。个股口径与主口径不一致时写这里，会接在财务表脚注「个别口径：」之后
  },
  rubric: { "卡脖子强度": 30, "下游覆盖": 25, "竞争格局": 20, "预期差": 15, "壁垒议价": 10 },

  themes: [{
    id: "cpo",
    query: "CPO / 光模块",        // 用户输入的产业链 / 热点 / 事件
    date: "2026-10-17",
    verdict: "一句话结论：卡点在哪一层、先研究谁",   // ≤70 字，必须给判断

    // ① 产业链层级（3–5 层，按卡点强度从高到低）
    layers: [{

      v: "优先研究",               // 优先研究 / 跟踪 / 观察 / 不优先
      cls: "v1",                   // v1 高亮 / v2 中间 / v3 灰

      confidence: "中",                        // 高/中/低

      position: "产业链位置：处在哪一层、上下游关系、替代路径",   // 60–100 字

        d: "2026-08-28",                 // 发布日期，必填

        src: "巨潮资讯",                 // 来源名，必填
        url: "https://...",              // 原文链接，强烈建议填；页面渲染为可点击的「来源名 ↗」

      }],
      risks: ["主要风险 1", "主要风险 2", "主要风险 3"],   // 2–4 条，第一条写最强反方

      gaps: ["还缺什么证据"],
      levels: { price: "142.60", fair: "118–126", add: "≤108", fail: "跌破 96" }

```

### 评分明细（第二个对象，必填）

五维卡片可点击展开，展开内容来自 `SCORE_NOTES`，**按股票代码索引**，与 `REPORT` 平级：

```js
const SCORE_NOTES = {
  "300308.SZ": {
    "卡脖子强度": {
      band: "27–30 档",                 // 该得分所属分数带，必须与 scoring-rubric.md 对齐
      plus: ["计入得分的具体事实 1", "事实 2", "事实 3"],   // 2–3 条，写事实不写形容词
      minus: ["未计满的原因"],                              // 1–2 条，诚实写差在哪
      basis: "2026 半年报（8/28）……；互动易（9/15）……",     // 判定依据，带日期
      verd: "给 27 不给 30：完整一句话说明为什么停在这一档"   // 必须解释边界
    },
    "下游覆盖": { band: "...", plus: [...], minus: [...], basis: "...", verd: "..." },
    "竞争格局": { ... },
    "预期差":   { ... },
    "壁垒议价": { ... }
  }
};
```

要求：
- **每只标的 × 5 个维度都要有**，缺一个，点开就是"未登记"，等于报告有洞
- `band` 必须能在 `scoring-rubric.md` 的分数带里找到，不能自创档位
- `verd` 是关键：必须回答"为什么不是上一档、也不是下一档"
- `plus` / `minus` 只写可核验的事实，形容词一律删掉

### 财务口径（第三个对象，必填）

放在产业链层级之后、标的列表之前，与 `SCORE_NOTES` 平级，**按股票代码索引**。目的是让读者在进入单家详情前，先用同一把尺子横向比一遍这几家公司的真实经营质量。

```js
const FIN = {
  "300308.SZ": {
    px:   "142.60",   // 收盘价（元），取 meta.priceDate 当日
    mcap: "1,180",    // 总市值（亿元，千分位字符串）
    pe:   "38.2",     // PE(TTM)，亏损或不可比填 "—"
    rev:  "+42",      // 营收同比（%，字符串，带正负号）
    np:   "+58",      // 归母净利同比（%）
    gm:   "34.1",     // 毛利率（%）
    gmd:  "+1.2",     // 毛利率较上年同期变动（pct）
    ocf:  "0.92"      // 经营现金流净额 ÷ 归母净利润（倍）
  },
  ...
};
```

规则：
- **每只入榜标的都要有一条**，缺失填 `"—"`，不得留空、不得估算
- 数字一律写成**带符号的字符串**（`"+42"` / `"-12"`），渲染层靠 `pct()` 补 `%`；写成数字会丢掉正负号
- 涨跌配色由 `cls()` 统一处理，模板已按 A 股习惯：**正红负绿**
- 表格 11 列固定：标的 / 层级 / 综合分 / 收盘价 / 市值(亿) / PE(TTM) / 营收 YoY / 净利 YoY / 毛利率 / 毛利率变动 / 现金流÷净利，**不许自行增删**
- 表尾脚注 `#finFoot` 由 `renderFin()` 自动生成，写清每个字段口径与数据来源，不要手改文案
- **口径不一致必须披露**：某个标的的同比不是同一报告期（如只有单季数据）、毛利率变动只有公司定性表述、或归母为负导致 PE 与现金流÷净利失真时，写进 `meta.finNote`，会在脚注末尾以「个别口径：……」出现。不写等于让读者把两套口径当一套看
- 表头左上角 `#finNote` 自动显示「报告期 X · 收盘 Y」，来自 `meta.finPeriod` / `meta.priceDate`

**财务口径与评分的关系**：财务是**验证**不是**打分**。分数已经在五维里定了，这张表用来暴露矛盾——比如分数高但营收增速为负、或净利增长靠非经常性收益（现金流÷净利明显低于 1）。发现矛盾时，要么在 `insight` 里解释，要么下调对应维度分数，**不能两张表各说各话**。

**字段质量要求**
- `position` 回答"它站在链条哪一段、谁卡它、它能卡谁"
- `why` 必须点名具体维度（如"竞争格局 14 把它拉下来"），不能只写"综合表现好"
- `risks` 不是风险清单，第一条要是能推翻论点的反方理由
- 同一主题内层级 `s` 与公司 `scores.卡脖子强度` 要互相解释：层级很卡但公司分数低，正说明这家公司不在该卡点的关键位置，报告里必须点出来

## 4. 评分与封顶

引擎实时计算，不在数据里写死总分：

- 总分 = 五维之和
- 按 `scoring-rubric.md` 执行封顶，页面显示"原始 X → 封顶 Y"与原因
- 定级：≥80 S 核心研究 / 65–79 A 重点跟踪 / 50–64 B 观察名单 / <50 C 暂缓
- 任一维度为 0 且标 `[MISSING]` → 显示"数据不足"，不给定级徽标
- 列表恒定按**封顶后**的分数降序

## 5. 交互清单

| 交互 | 行为 |
|---|---|
| 主题 chips | 切换主题，重置选中为最高分标的 |
| 标的行 | 点击选中，右侧详情与分数环同步；<900px 自动滚到详情 |
| **五维卡片** | **点击展开该维度的得分明细（分数带 / 计入得分 / 未计满 / 判定依据 / 结论），再点收起；展开时卡片显示高亮与 `aria-expanded`** |
| 财务表 | 按综合分排序，与左侧榜单顺序一致；窄屏横向滚动；行可 hover 高亮，不参与选中联动 |
| 证据来源 | `evidence[].url` 存在时渲染为外链，新窗口打开（`rel="noopener noreferrer"`），带 `↗` 标记；`page` 以「· 第 X 页」形式跟在来源名后 |
| 复制结论 | 复制"主题 + 层级排序 + 首选标的 + 总分 + 一句话结论 + 最大未解问题" |
| 键盘 | 标的行与维度卡均可 Tab，Enter/Space 触发，焦点环可见 |

**已删除**：顶栏搜索框与分析按钮。报告是单次研究的静态快照，页面内无法真正检索外部数据，保留只会让读者误以为可以查新主题。

## 6. 视觉规范（Apple 液态玻璃）

**材质**
- 卡片 `rgba(255,255,255,.58)` + `backdrop-filter: blur(26px) saturate(200%)`
- 双层描边：外 `1px rgba(255,255,255,.62)`，内 `inset 0 1px 0 rgba(255,255,255,.92)`
- 阴影 `0 24px 60px -26px rgba(30,28,60,.30)`，禁止纯黑重阴影
- 圆角：大卡 22px / 中卡 16px / 胶囊 999px
- 背景：固定环境光渐变（4 个柔光团 + 线性底）+ 3 个缓慢漂移光斑，不用图片

**排版**
- `-apple-system, "SF Pro Text", "PingFang SC", system-ui`
- 正文 13.5/1.65；标签 10.5–11px + `letter-spacing .05em` 且降一级颜色
- 大数字 `tabular-nums`、字距 `-.03em`、字重 650–700

**动效**
- 弹簧 `cubic-bezier(.22,1.2,.36,1)` 320–420ms；hover 位移 ≤2px；按下 `scale(.97)`
- 分数环用 `stroke-dashoffset` 过渡，列表分数条用 `width` 过渡；不做旋转特效

**降级（缺一不可）**
- `prefers-reduced-motion: reduce` → 1ms
- `prefers-reduced-transparency: reduce` → 实色 `#fff` + 关闭 `backdrop-filter`
- `prefers-color-scheme: dark` → 深色玻璃 + 浅色文字，正文对比度 ≥4.5:1
- `prefers-contrast: more` → 描边 1.5px，文字提到纯黑/纯白

## 7. 自检清单（交付前逐条过）

1. 层级是不是 3–5 层，且第一层能解释"为什么这条链卡在这里"？
2. 标的 3–5 只，是否覆盖了至少两个不同层级？只覆盖一层的，说明层级分析没落地。
3. 每只标的的 `position` 与 `why` 是不是都能对上 `scores` 里的具体数字？
4. **`SCORE_NOTES` 是否覆盖了每只标的的每个维度（N × 5）？点开五个维度是否都有内容、都有 `verd` 解释边界？**
5. **`FIN` 是否覆盖了全部入榜标的？11 列是否都填了（缺的写 `"—"`）？`meta.finPeriod` 与 `meta.priceDate` 是否已填？有没有哪只标的是另一套口径却没写进 `meta.finNote`？**
6. **财务表有没有和分数打架？**分数高但营收负增长、净利增长但现金流÷净利 <0.6、毛利率下滑却给高分——每一处矛盾要么写进 `insight` 解释，要么下调分数。
7. 有没有一只标的是"层级很卡但公司分数低"？如果有，报告里是否解释了原因？
8. 证据是否全部带日期与来源？能与原文对应的，是否补了 `url` 与 `page`？缺口是否写进 `gaps` 而不是含糊带过？
9. 页面上是否还残留搜索框、顶栏或"分析"按钮？（应为 0，报告不提供检索）
10. 三种宽度（1440 / 1080 / 420）打开有没有横向滚动条？财务表在 420px 下是否为容器内滚动而非整页溢出？深色下文字与涨跌色是否可读？
11. `meta.demo` 是否已置 `false`，演示数值是否清空？
